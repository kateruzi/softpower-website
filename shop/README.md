# Сервис магазина

Принимает заказы с `merch.html` / `merch-en.html`: считает деньги, ведёт оплату
картой через stripe, складывает заказы в postgres и пишет о каждом в телеграм.

## Как это работает

Страница мерча — обычная статика. При открытии она спрашивает у сервиса
`GET /api/health`. Ответил — витрина начинает принимать заказы по-настоящему.
Не ответил (сервис не поднят, погашен рубильником или без ключей оплаты) —
кнопка «оформить заказ» просто показывает, что ушло бы на сервер. Никаких
флажков в js переставлять не надо.

Два пути заказа:

- **картой.** `POST /api/checkout` → сервис заводит заказ и отдаёт адрес
  страницы оплаты. Покупатель платит, stripe дёргает `POST /api/stripe/webhook`,
  заказ становится `paid`, в телеграм уходит алерт, покупателя возвращает на
  «спасибо».
- **при встрече.** `POST /api/order` → заказ сразу заводится как `cash_pending`,
  алерт уходит немедленно, покупатель попадает на «спасибо».

Цены сервис берёт **только** из `shop/catalog.json`. Цена на странице — это
надпись: её можно поправить в браузере, и на сумму заказа это не повлияет.

## Что где менять

| Что | Где |
|---|---|
| фото, тексты, какие бывают варианты | `js/merch-catalog.js` |
| цены, остатки | `shop/catalog.json` |
| токен бота, ключи stripe, порты | `.env` рядом с `docker-compose.yml` |

Добавила товар на витрину — добавь его и в `shop/catalog.json` с тем же `id`.
Сервис при старте сверяет оба файла и, если они разъехались, пишет об этом
в телеграм: купить товар, которого нет в серверном каталоге, нельзя.

После правки `shop/catalog.json` достаточно перезапустить сервис:
`docker compose restart shop`. Пересобирать образ не нужно.

## Запуск

```bash
cp .env.example .env      # и заполнить
docker compose up -d --build
curl -s localhost:$WEB_PORT/api/health
```

Заказы живут в postgres, в volume `shop_pgdata`. Контейнеры можно удалять
и поднимать заново сколько угодно — данные в них не хранятся.

## Рубильник

`SELLING=0` в `.env` и `docker compose up -d shop` — витрина остаётся, приём
заказов останавливается. Так можно закрыть магазин, не трогая сайт.

## Тестовый шлюз оплаты

`DEV_FAKE_PAYMENTS=1` (только staging, в prod сервис с таким флагом не
стартует) подменяет страницу stripe своей: там кнопки «оплатить» и «отменить».
Дальше всё идёт ровно тем же кодом, что и настоящая оплата, поэтому проверять
«что будет после оплаты» можно до появления ключей stripe.

## Когда появятся ключи stripe

1. `STRIPE_SECRET_KEY` в `.env`, `DEV_FAKE_PAYMENTS=0`.
2. В личном кабинете stripe завести вебхук на `https://<домен>/api/stripe/webhook`,
   событие `checkout.session.completed`, его секрет — в `STRIPE_WEBHOOK_SECRET`.
3. `docker compose up -d shop`.

Stripe Price ID не нужны: сервис передаёт цену из своего каталога в момент
оплаты, поэтому заводить товары ещё и в stripe не придётся.

## Устройство

```
app/config.py    всё, что берётся из окружения
app/catalog.py   цены и варианты, разбор sku вида hoodie|size:lxl
app/orders.py    заказ: собрать, сохранить, отметить оплату, известить
app/payments.py  stripe и тестовый шлюз за одним интерфейсом
app/notify.py    telegram bot api
app/api.py       http: проверить вход → позвать логику → ответить
```
